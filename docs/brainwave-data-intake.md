# 脳波データ取り込み仕様

最終更新: 2026年8月16日
測定機器: FocusCalm（iPad アプリ）

## 扱うデータ

1分測定から得られる7波形を扱う。

| チャンネル | 表示名 | 利用者向け画面 | カルテ（管理者） |
|---|---|---|---|
| `relax` | リラックス | 表示する | 表示する |
| `focus` | 集中 | 表示する | 表示する |
| `alpha` | α波 | 表示しない | 表示する |
| `beta` | β波 | 表示しない | 表示する |
| `gamma` | γ波 | 表示しない | 表示する |
| `delta` | δ波 | 表示しない | 表示する |
| `theta` | θ波 | 表示しない | 表示する |

**α/β/γ/δ/θ の5帯域は、利用者向け画面に出さないだけで、必ず保管する。**
初期段階でリラックス・集中のみ見せるのは表示上の判断であり、データを捨ててよいという意味ではない。
後から解析や表示方針の変更ができるよう、元CSVもそのまま保持する。

定義は `src/types/brainwave.ts`。

## 取り込み経路は2つある

### 経路1: CSV（グラフの正データ）

FocusCalm から書き出した CSV を取り込む。これがグラフ描画の**正データ**。

- パーサ: `src/lib/brainwaveCsv.ts`
- 列名は完全一致ではなく別名テーブルで照合する。機器やアプリのバージョンで
  列名が変わっても壊れないようにするため。以下すべて同じ `relax` として解釈する。
  `Relax` / `Calm Score` / `calmness` / `リラックス値` / `リラックス度`
- 列の順序に依存しない。メモ列など未知の列が混ざっていても無視する。
- 時刻列は以下を自動判別する。
  - 秒数値（`0, 1, 2, ...`）
  - ミリ秒エポック（`1767225600000, ...` → 秒へ換算）
  - `mm:ss` / `hh:mm:ss` 表記
  - ISO日時
  - 時刻列そのものが無い場合は行番号を1秒間隔として扱う
- 引用符内のカンマ・改行を正しく処理する（`split(",")` は使っていない）。
- 数値が1つも入っていない行は読み飛ばす。一部チャンネルだけ欠損している行は
  直前値を引き継ぎ、時系列の長さを揃える。
- CSVに無いチャンネルは `missingChannels` として記録し、画面に明示する。

取り込み時の注意点（時刻の単位換算、読み飛ばした行数、欠損チャンネル）はすべて
`warnings` として画面に出す。**黙って補正しない。**

### 経路2: iPad スクリーンショット（証跡）

1画面に2グラフが写り、4枚撮ると重複を含みながら7波形が揃う運用に対応する。

- 取り込み: `src/lib/screenshotIntake.ts`
- **重複除去は自動で行う。** 各画像を16x16のグレースケールに縮小して平均輝度で
  2値化した知覚ハッシュ（average hash）を計算し、ハミング距離が閾値以下なら
  同一グラフとみなして除外する。既存画像とも、同じバッチ内の他の画像とも比較する。
- **波形種別の自動判定はファイル名からのみ行う。** 画像内の文字を読む OCR は実装していない。
  ファイル名に `relax` `集中` `alpha` `α` 等が含まれていればそれを初期値にする。
  判定できない場合は空のまま取り込み、操作者がタグを付ける。

#### なぜ画素からの自動ラベル付けをしないのか

グラフのタイトル文字を画像から読むには OCR が必要で、iPad の解像度・
アプリのテーマ・スクショの切り取り位置によって精度が大きく変わる。
**誤判定した波形が「集中」として保存されると、カルテとして信用できなくなる。**
判定精度を保証できない処理を自動で確定させるより、重複除去（確実にできる）だけを
自動化し、種別は操作者が確認する構成にしている。

画面上は次の形で確認できるようにしてある。

- 各画像のカードに7チャンネルのタグボタンが並び、クリックで割り当てを切り替えられる
- 判定根拠（「ファイル名から推定」か「操作者が手動で指定」か）をカードに表示する
- まだどの画像にも割り当てられていない波形があれば警告として出す

CSV を取り込んでいれば、グラフはCSVから描画されるので、スクリーンショットは
「測定時に実際にこの画面が出ていた」という証跡としての役割になる。

## 保存先

`supabase/schema.sql` に以下を定義済み。

- `brainwave_sessions` — CSV 1本 = 1行。`timestamps_sec`（配列）、`series`（jsonb）、
  `missing_channels`、`stats`、`raw_csv_path`（元CSVの Storage パス）
- `brainwave_screenshots` — 画像1枚 = 1行。`channels`（配列）、`content_hash`（重複判定用）、
  `detection_reason`

RLS は**本人と管理者のみ**。認定インストラクターであっても、他の利用者の測定値は参照できない。
脳波は個人の健康に関わる情報のため、ベースブレンド情報より厳しい範囲にしている。

Storage には以下のバケットが必要。

- `aroma-images`（既存）
- `brainwave-screenshots` — 測定画面のスクリーンショット
- `raw-brainwave-csv` — 元CSVの保管

## 現状の実装範囲

現行版はブラウザ内 state で動作する。CSVのパース、グラフ描画、重複除去、
タグ付けはすべて実際に動くが、**Supabaseへの永続化は未接続**。
`brainwave_sessions` / `brainwave_screenshots` へ書き込むサービス層が次の作業になる。
