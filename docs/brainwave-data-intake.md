# 脳波データ取り込み仕様

最終更新: 2026年8月26日
測定機器: FocusCalm（iPad アプリ）

## 扱うデータ

1分測定から得られる7波形を扱う。

| チャンネル | 表示名 | 利用者向け画面 | カルテ（管理者） |
|---|---|---|---|
| `relax` | リラックス | 表示する | 表示する |
| `focus` | 集中 | 表示する | 表示する |
| `alpha` | α波 | 表示しない | 表示する |
| `beta` | β波 | 表示しない | 表示する |
| `gamma` | γ波 | 表示しない | 表示する |
| `delta` | δ波 | 表示しない | 表示する |
| `theta` | θ波 | 表示しない | 表示する |

**α/β/γ/δ/θ の5帯域は、利用者向け画面に出さないだけで、必ず保管する。**
初期段階でリラックス・集中のみ見せるのは表示上の判断であり、データを捨ててよいという意味ではない。
後から解析や表示方針の変更ができるよう、元CSVもそのまま保持する。

定義は `src/types/brainwave.ts`。

## 取り込み経路は2つある

### 経路1: CSV（グラフの正データ）

FocusCalm から書き出した CSV を取り込む。これがグラフ描画の**正データ**。

- パーサ: `src/lib/brainwaveCsv.ts`
- 列名は完全一致ではなく別名テーブルで照合する。機器やアプリのバージョンで
  列名が変わっても壊れないようにするため。以下すべて同じ `relax` として解釈する。
  `Relax` / `Calm Score` / `calmness` / `リラックス値` / `リラックス度`
- 列の順序に依存しない。メモ列など未知の列が混ざっていても無視する。
- 時刻列は以下を自動判別する。
  - 秒数値（`0, 1, 2, ...`）
  - ミリ秒エポック（`1767225600000, ...` → 秒へ換算）
  - `mm:ss` / `hh:mm:ss` 表記
  - ISO日時
  - 時刻列そのものが無い場合は行番号を1秒間隔として扱う
- 引用符内のカンマ・改行を正しく処理する（`split(",")` は使っていない）。
- 数値が1つも入っていない行は読み飛ばす。一部チャンネルだけ欠損している行は
  直前値を引き継ぎ、時系列の長さを揃える。
- CSVに無いチャンネルは `missingChannels` として記録し、画面に明示する。

取り込み時の注意点（時刻の単位換算、読み飛ばした行数、欠損チャンネル）はすべて
`warnings` として画面に出す。**黙って補正しない。**

### 経路2: 測定画面のスクリーンショット

測定アプリ（ローカル計測）の画面を撮り、**グラフを1枚ずつ自動で切り出して**保管する。
操作者が iPad 上で切り抜く作業は不要。

実装: `src/lib/screenshotSplit.ts`（切り出し）、`src/lib/screenshotIntake.ts`（重複除去）

#### 画面の構造

実機のスクリーンショットは次の構造になっている。

- 背景は水色（明るい）
- グラフは**黒に近いダークカード（角丸）**として縦に並ぶ
- 上部にヘッダー（X / ローカル計測 / 脳アイコン）
- 下部に「脳波データを転送」（白ボタン）と「再計測」（黒ボタン）

したがって「画像を上下半分に割る」方式は使えない。
代わりに**暗いカードを検出して、完全に写っているものだけを取り出す**。

1. 各行について「暗い画素が占める割合」を求め、半分以上ならカード内とみなす
2. 連続する行をまとめてカード候補にする（角丸の欠けは埋める）
3. いちばん大きいカードの半分未満の高さのものを落とす
   → 「再計測」ボタン（黒くて短い）と、下端で切れたカードがここで外れる
4. カードごとに左右の端を求めて切り出す

1画面に写る枚数を決め打ちしていないので、端末の向きを問わず動く。

#### 端末の向きによる違い

| 撮り方 | 1画面のグラフ | 7波形に必要な撮影回数 | 切り出しサイズの例 |
|---|---|---|---|
| **iPad 縦（推奨）** | 3つ（＋下端に切れた4つ目） | **3回** | 952×308 |
| iPad 横 | 2つ | 4回 | 1294×353 |
| iPhone 縦 | 2つ | 4回 | 358×309 |

**iPad 縦を推奨する。** 撮影回数がいちばん少なく、グラフの大きさも十分に確保できる。
横向きはグラフが広く写るが撮影回数が1回増える。

3パターンとも、実機の画面を再現したモックで検証し、いずれも7波形が残ることを確認済み。

#### 重複の除去

複数回撮ると同じグラフが重複して入る。これを落とすため、
切り出した画像どうしを差分ハッシュ（dHash, 32x32 = 1024bit）で比較する。

実測したハミング距離:

| 比較 | 距離 |
|---|---|
| 同一グラフ（手書きの重なり方が違うだけ） | 7 |
| 別の波形どうし | 66 / 71 / 72 |

明確に分かれるので、しきい値は中間よりやや厳しい **24** とした。
誤って別の波形を消すほうが、重複が1枚残るより損失が大きいため
（残った重複は操作者が消せるが、消えたグラフは戻らない）。

平均ハッシュ（aHash）は、白背景でも暗背景でも別グラフを重複と誤判定したため採用していない。

#### 手書きの注釈について

スクリーンショットに黄色や赤のペンで書き込みがある場合、
**検出には影響しない**（カードの暗さは保たれるため）。
ただし切り出した画像には書き込みがそのまま残る。
グラフの線（オレンジ・青）と色が近く、消そうとすると波形まで削る危険があるため、
自動での消去は行っていない。

#### 波形の種類の判別

**画像から種類を読むことはしていない。** OCR は端末の解像度・切り取り位置で精度が変わり、
誤判定した波形が「集中」として保存されるとカルテとして信用できなくなるため。

代わりに次の順で決める。

1. ファイル名にヒントがあればそれを使う
2. 「撮影順で一括割り当て」ボタン（リラックス → 集中 → α → β → γ → δ → θ）
3. 各カードのタグで操作者が指定・修正

## 保存先

`supabase/schema.sql` に以下を定義済み。

- `brainwave_sessions` — CSV 1本 = 1行。`timestamps_sec`（配列）、`series`（jsonb）、
  `missing_channels`、`stats`、`raw_csv_path`（元CSVの Storage パス）
- `brainwave_screenshots` — 画像1枚 = 1行。`channels`（配列）、`content_hash`（重複判定用）、
  `detection_reason`

RLS は**本人と管理者のみ**。認定インストラクターであっても、他の利用者の測定値は参照できない。
脳波は個人の健康に関わる情報のため、ベースブレンド情報より厳しい範囲にしている。

Storage には以下のバケットが必要。

- `aroma-images`（既存）
- `brainwave-screenshots` — 測定画面のスクリーンショット
- `raw-brainwave-csv` — 元CSVの保管

## 現状の実装範囲

現行版はブラウザ内 state で動作する。CSVのパース、グラフ描画、重複除去、
タグ付けはすべて実際に動くが、**Supabaseへの永続化は未接続**。
`brainwave_sessions` / `brainwave_screenshots` へ書き込むサービス層が次の作業になる。
